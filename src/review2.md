# Laravel Lesson レビュー②

## Todo編集機能
  - Todo編集機能を実装するには、まず編集画面のルートを設定し、次にそのTodoのデータを表示するためにコントローラでeditメソッドを作ります。フォームでは、ユーザーがTodoの内容を編集できるようにし、送信時にPUTメソッドを使って変更を送信します。コントローラのupdateメソッドでは、送信されたデータをバリデーションし、Todoの内容を更新して保存します。編集が終わったら、Todo一覧ページにリダイレクトします。

### @method('PUT')を記述した行に何が出力されているか
  - @method('PUT')は、HTMLフォームでPUTメソッドを使ってリクエストを送信するために必要な記述です。HTMLのフォームは通常GETまたはPOSTメソッドで送信されますが、PUTメソッドを使いたい場合、HTMLでは直接PUTを指定できません。そのため、Laravelでは@method('PUT')を使ってPOSTメソッドをPUTメソッドに変換します。

### findメソッドの引数に指定しているIDは何のIDか
  - findメソッドの引数に指定しているIDは、データベース内で検索したい特定のレコードのIDです。

### findメソッドで実行しているSQLは何か
  - SELECT * FROM todos WHERE id = ? LIMIT 1;
  - ?の部分には、findメソッドに渡された$idの値が入ります。

### findメソッドで取得できる値は何か
  - findメソッドで取得できる値は、指定されたIDに対応するレコードのデータです

### saveメソッドは何を基準にINSERTとUPDATEを切り替えているのか
  - INSERT(新規挿入)新しいTodoオブジェクトを作成し、まだデータベースに保存されていない場合（つまり、IDが設定されていない場合）、saveメソッドは新しいレコードをデータベースに挿入します。
  - Todoオブジェクトがデータベースにすでに存在し、IDが設定されている場合（例えば、findメソッドで既存のレコードを取得した場合）、saveメソッドはそのレコードを更新します。

## Todo論理削除
  - Todo論理削除の手順は、まずモデルにuse Illuminate\Database\Eloquent\SoftDeletes;を追加して、論理削除機能を有効にします。次に、マイグレーションを修正して、deleted_atというカラムを追加します。このカラムは、削除された日時を記録するために使用されます。その後、delete()メソッドを呼び出すと、データは削除されるのではなく、deleted_atカラムに削除日時が設定されます。このようにして、データは実際に削除されることなく、削除と復元を管理することができます。
### traitとclassの違いとは
  - trait と class の違いは、主に役割と使い方にあります。class はオブジェクト指向プログラミングでオブジェクトを作成するための設計図であり、属性や動作を持つことができます。一方、trait はクラスに機能を追加するためのもので、複数のクラスで共通のメソッドを使えるようにするために使われます。class はインスタンス化されてオブジェクトとして使用されますが、trait はインスタンス化されることはなく、クラスに組み込まれて使われます

### traitを使用するメリットとは
  - trait と class の違いは、主に役割と使い方にあります。class はオブジェクト指向プログラミングでオブジェクトを作成するための設計図であり、属性や動作を持つことができます。一方、trait はクラスに機能を追加するためのもので、複数のクラスで共通のメソッドを使えるようにするために使われます。
## その他

### TodoControllerクラスのコンストラクタはどのタイミングで実行されるか
  - TodoController クラスのコンストラクタは、コントローラがインスタンス化されるタイミングで実行されます。Laravelでは、リクエストが来ると、指定されたコントローラのアクション（例えば、index や create など）が呼び出され、その前にコンストラクタが自動的に呼び出されます。

### RequestクラスからFormRequestクラスに変更した理由
  - Request クラスから FormRequest クラスに変更する理由は、フォームのバリデーションを簡単に管理するためです。FormRequest クラスを使用すると、バリデーションルールや認可ロジックを専用のクラスに分けて整理でき、コントローラをシンプルに保つことができます。また、バリデーションが自動で実行され、失敗した場合はエラーメッセージを返すため、セキュリティやコードの保守性も向上します。

### $errorsのhasメソッドの引数・返り値は何か
  - $errorsのhasメソッドは、引数として指定したフィールド（例えば、'content'など）にエラーがあるかどうかを確認します。このメソッドは、該当するエラーが存在する場合にtrueを返し、存在しない場合にはfalseを返します。引数にはフィールド名（文字列）を指定します。

### $errorsのfirstメソッドの引数・返り値は何か
  - 引数: $errors->first メソッドは、フォームの入力フィールドの 名前（例: 'content'）を引数として受け取ります。この引数は、どのフィールドに対してエラーメッセージを取得したいかを指定します。
  - 返り値: このメソッドは、指定されたフィールドに関連する 最初のエラーメッセージ を返します。もしエラーがなければ、null を返します。

### フレームワークとは何か
  - フレームワークとは、アプリケーション開発を効率よく行うために用意された 事前に構築されたコードやライブラリの集まり です。開発者は、フレームワークを使うことで、繰り返し行う作業を簡略化し、標準的な手法で開発ができるようになります。

### MVCはどういったアーキテクチャか
  - MVCは、アプリケーションの設計方法で、Model（モデル）、View（ビュー）、Controller（コントローラー）の3つの部分に分けて管理されます。Modelはデータやビジネスロジックを扱い、Viewはユーザーに表示する部分を担当し、ControllerはModelとViewをつなげる役割を果たします。この構造を使うことで、コードが整理され、保守性や拡張性が向上します。

### ORMとは何か、またLaravelが使用しているORMは何か
  - ORM（Object-Relational Mapping）とは、オブジェクト指向プログラミングのオブジェクトと、リレーショナルデータベースのデータとの間で自動的に変換を行う技術です。これにより、データベースのテーブルとコード上のオブジェクトを対応させ、SQLを書くことなくデータの操作が可能になります。

### composer.json, composer.lockとは何か
  - composer.jsonこのファイルには、プロジェクトが依存しているパッケージやライブラリの情報が記載されています。
  - composer.lockこのファイルは、composer.json に基づいて実際にインストールされたパッケージのバージョンを記録したファイルです。プロジェクトを他の開発者と共有する場合、このファイルを使うことで、全員が同じバージョンのパッケージを使用できるようにします。

### composerでインストールしたパッケージ（ライブラリ）はどのディレクトリに格納されるのか
  - Composerでインストールしたパッケージ（ライブラリ）は、プロジェクトのルートディレクトリにある vendor ディレクトリに格納されます。
